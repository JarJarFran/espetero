## 0.1.0 (2026-10-11)

The first public release.

- **Models**: the Qwen3.5 family (Qwen3.5, Qwen3.6, Qwen3.8 and their finetunes), dense and mixture-of-experts, with vision and MTP heads, from MLX safetensors or GGUF (also mixture-of-experts files whose quantization differs by layer, as unsloth's UD files do), local or by Hugging Face repo id; Qwen3.8-Flash-Next with its experts streamed from the SSD. Other model types are refused at start with a message naming their type.
- **Gemma 4**: the 31B dense and 26B-A4B mixture-of-experts models from MLX safetensors (checked on 4- and 6-bit files) and llama.cpp `gemma4` GGUF (checked on UD-Q4_K_M), text only: sliding-window layers with a ring of KV blocks per sequence slot, global layers with K = V and proportional RoPE in the paged pool, GeGLU, the router with per-expert scales beside the dense MLP, soft-capped logits; its SentencePiece-style tokenizer (byte fallback, token for token equal to `tokenizers`, from `tokenizer.json` or the GGUF vocabulary), the thinking channel as `reasoning_content`, its `<|tool_call>` calls as OpenAI `tool_calls`, structured output, embeddings, prompt checkpoints and prompt-lookup drafts; raw completions and embeddings start with `<bos>`, as llama.cpp's do. Greedy replies equal mlx-lm's (fp32 reference) and llama.cpp's on the same files.
- **Model handling**: repo ids download natively (no Python) into the Hugging Face cache, in huggingface_hub's own layout, so `hf`, transformers, mlx-lm and Espetero share one copy (resumable, checksummed); a model that cannot fit this Mac is refused before its download or load, with smaller files of the same model suggested; `espetero recommend` lists the models that fit this Mac (8-bit first), and `espetero pull`, `list` and `rm` manage the models in the cache and in `~/models`.
- **APIs**: OpenAI chat completions and completions (streaming, `n` choices from one prefill, logprobs of greedy, sampled and streamed replies, tools with `tool_choice` `required` or a named function, images as data URLs and, with `--image-urls`, by URL), structured output (`response_format` `json_object` and `json_schema`, Responses `text.format`, Anthropic `output_config.format`, Ollama `format`: the reply is constrained by a grammar compiled from the schema), Responses, embeddings of the loaded model, Files and Batches; Anthropic Messages (Claude Code works against it); Ollama's API (chat, generate, embeddings, model listing; replies equal the chat route's); `/v1/decisions`; tokenize and detokenize; Prometheus metrics.
- **Engine**: one GPU pass per step for all the work in flight, paged KV cache with shared prefixes, prompt checkpoints in memory and on disk, speculative decoding with the model's MTP head and prompt lookup (verified: replies do not change), reproducible seeded sampling, budgets sized from the Mac; weights read with parallel preads (a 28 GB MoE loads in ~12 s instead of 34-49 s); decode attention reads the KV cache at ~350 GB/s at long contexts (a decode step at 32K context: Qwen3.8-27B 105 -> 77 ms, Qwen3.6-35B-A3B 22 -> 14 ms, Gemma 4 31B 173 -> 85 ms); in the general preset a new request waits at most 200 ms for running replies before its prompt runs beside them (first token 1.1 s instead of 3.6 s on the 27B while another reply streams).
- **Robustness**: a request starts once the KV cache can hold its prompt and its `max_tokens` (counted up to 8K tokens or a quarter of the cache) beside the running ones, and cached checkpoints are evicted for it only when that lets it start; if the cache still runs out, a pass skips its prompts' optional checkpoints, then prompt chunks wait, then the newest requests stop with an error that says what would fit and the others finish (a request alone fills the cache to its last block). Images and decisions too large for one pass get a 422 naming `--max-rows`; a decision that fits one waits at most 4 passes beside decoding requests. Streams that fail end with an error event and `[DONE]`. Ctrl-C ends running requests after the current pass.
- **Server**: the port opens before the model loads (a port in use fails at once; requests get 503 `{"status": "loading"}` until the model is ready); a built-in web chat at `/` (one embedded page, no other origin, a strict Content-Security-Policy); a default configuration file (`~/.config/espetero/config.json`); `espetero service install|status|logs|uninstall` (a LaunchAgent: at login, restarted if it fails) and `brew services`.
- **Security**: localhost by default; bounded request, image, upload and batch sizes; requests from web pages refused without an API key; image URLs off by default and never fetched from this machine or its networks unless `--image-urls-private`.

Known limitations:

- One trusted user: every API key holder shares the prompt cache and the Batch API.
- Not supported yet (422, never ignored): `logit_bias`, images by file id or inside tool results, built-in or server tools; in a strict JSON schema, the keywords the grammar cannot enforce (`pattern`, `format`, `multipleOf`, `uniqueItems`, ...; non-strict schemas report them instead). Forced tool calls need a chat template with Qwen's `<tool_call><function=...>` format.
- Gemma 4 runs text only: images get a 422, forced tool calls (`tool_choice` `required` or a named function) get a 422, and the E2B/E4B models (per-layer embeddings, KV-shared layers) are refused at load.
- Embeddings are the chat model's own hidden states; dedicated embedding models (Qwen3-Embedding) are not supported yet, and Qwen3.8-Flash-Next cannot serve them.
- Answers longer than 8K tokens (or a quarter of the KV cache) are not reserved in full: when many such answers run at once and the cache fills, the newest stop with a "KV cache full" error. Raise `--memory-gb` or `--kv-gb` for those workloads.
- With `--image-urls`, a host name that resolves to a public address for the check and to a private one for the connection (DNS rebinding) still receives one GET; its answer is discarded.
- On mixture-of-experts models (Qwen3.6-35B-A3B, Gemma 4 26B-A4B) a request that shares a pass with others or starts from a prompt checkpoint can pick another expert at a near-tied token, so its greedy reply can differ from there from the same request alone (dense models: log-probabilities within 0.02 nats). Drafts left replies unchanged in every test.
- One model per server: there is no loading of other models on demand.
- Tuned and tested on an M1 Max (64 GB) with macOS 26. The binary targets macOS 15 or later, but has not run on macOS 15 yet. The first start of a newly installed binary compiles the GPU kernels (5-6 s); later starts reuse them.
