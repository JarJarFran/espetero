# Espetero 0.1.2 against the other engines: Mac Studio M4 Max

Mac Studio with an M4 Max (128 GB), measured on 2026-10-26 and 2026-10-27.
The protocol is the one in [README.md](README.md#method): the same client,
[tools/bench_compare.py](../../tools/bench_compare.py), greedy decoding with
thinking off, 16 parallel slots and a 40K context in every server, and the
median over each cell's requests. Each run was an exclusive gputurn job with
the GPU to itself. Every request is in
[2026-10-27-m4-max.jsonl](2026-10-27-m4-max.jsonl).

Engines: Espetero 0.1.2 (d1862cc; the Flash-Next 16-user rows with 6c0c657,
see below), llama.cpp b11429, mlx-lm 0.32.2, oMLX 0.7.2, BaseRT 0.3.0. Server
flags as in the README, with `--prefix-dir none` for Espetero.

- **Fewer competitor workloads.** The other engines ran decode, code, prefill
  1K and 8K, 8 and 16 users and the image: no 4 users, no decode after a long
  context, no 32K prompt, no answer checks. Espetero ran the full set. Empty
  cells (–) in the other engines' columns are workloads they did not run, not
  failures.
- **Espetero, Qwen3.8-Flash-Next, 16 users**: build d1862cc gave the server
  exactly 16 slots, and in the 16-user run the slowest request waited about
  25 s for its first token. 6c0c657 gives the server two more slots than
  users; its rows replace d1862cc's in that line (152.1 and 154.5 tok/s,
  against 138.2 and 143.7; slowest first token 1.4 s against 25 s). With 1, 4
  and 8 users the two builds measured within 4 % of each other.
- **oMLX** on the Flash-Next oQ4e file turns on the file's MTP head from its
  model preset; its column is oMLX as it ships, with MTP. Its preset also
  sets temperature 1.0, but it honours the request's temperature 0: the same
  prompt three times gave three identical replies (70–78 % of drafts
  accepted).
- **llama.cpp + MTP** ran on Qwen3.8-27B only; there is no Flash-Next MTP
  drafter for it in these runs. The unsloth Qwen3.8-Flash-Next GGUF was left
  out: at 111 GB it loads from the Mac Studio's hard disk, so its rows measure
  that disk.
- **Load time** depends on whether the files were already in memory; it is
  not comparable between columns.
